# TwinSight — تیم BridgeX

**پیش از تغییر نرم‌افزار، فرصت‌ها و ریسک‌های آن را ببینید.**

TwinSight نمونهٔ نمایشی دوقلوی نرم‌افزاری سازمان است: یک تغییر پیشنهادی را روی دانش مشترک سازمان بررسی می‌کنیم تا اثر آن بر سرویس‌ها، مشتری و کسب‌وکار روشن شود. هدف محصول آینده، دریافت پیوستهٔ بک‌لاگ، تیکت، کد و دادهٔ عملیاتی و تحلیل فرصت و ریسک با AI و ارجاع به شواهد است.

## این MVP چه کاری انجام می‌دهد؟

- سه سناریوی آماده: خرید بدون ثبت‌نام، رفع پرداخت تکراری و جست‌وجوی سریع‌تر.
- نمایش وابستگی‌ها و مسیر اثر روی شش بخش نرم‌افزار فروشگاه ساختگی «سپهر تجارت».
- مقایسهٔ انتشار کامل، شروع محدود و گسترش، و تعویق سه‌ماهه.
- جداسازی منفعت ناخالص، هزینهٔ ساخت و اجرا و بازهٔ منفعت خالص.
- نمایش ریسک‌ها، شواهد، اطلاعات موردنیاز و معیار توقف.
- ورود یک تیکت ساختگی و محاسبهٔ دوبارهٔ تحلیل ثبت‌شده با نسخهٔ تازهٔ دانش سازمان.
- ثبت تصمیم اولیهٔ انسان در حافظهٔ صفحه و دریافت گزارش JSON یا چاپ مرورگر.

**تمام داده‌ها، رابطه‌ها، هزینه‌ها، شاخص‌ها و بازه‌ها فرضی‌اند.** هیچ LLM، اتصال زنده، تحلیل معنایی متن یا مدل پیش‌بینی آموزش‌دیده اجرا نمی‌شود. شاخص ریسک احتمال خرابی نیست. یادداشت کاربر فقط در گزارش ثبت می‌شود. بازهٔ منفعت، تحلیل حساسیت با ضرایب فرضی است و بازهٔ اطمینان آماری نیست. زیان اختلال و هزینهٔ اشتراک TwinSight در محاسبه نیامده‌اند.

## اجرا

Node.js 22 یا جدیدتر کافی است؛ وابستگی npm نداریم.

```bash
npm run dev
```

http://localhost:8080 را باز کنید. برای پورت دیگر:

```bash
npm run dev -- --port 8081
```

اگر Python موجود است، برای نمایش بدون Node:

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory public
```

فایل HTML را مستقیم با `file://` باز نکنید؛ ماژول و JSON به HTTP نیاز دارند. فونت و همهٔ فایل‌ها محلی‌اند؛ پس از دریافت فایل‌ها، اجرای محلی اینترنت نمی‌خواهد.

## مسیر دمو، حدود دو دقیقه

1. سناریوی «خرید بدون ثبت‌نام» را مرور کنید: فرصت خرید بیشتر، همراه با ریسک سفارش و پرداخت.
2. مسیر اثر را در نقشه ببینید و شاهد وابستگی سفارش را باز کنید.
3. انتشار کامل را با شروع محدود مقایسه کنید؛ منفعت پایلوت دیرتر حاصل می‌شود.
4. در «دانش سازمان»، «ورود تیکت نمونه» را بزنید؛ مدل و تحلیل به نسخهٔ ۲ می‌روند.
5. به بررسی تغییر برگردید؛ شاهد جدید و تغییر شاخص را ببینید.
6. تصمیم اولیه را ثبت کنید و گزارش تصمیم را دریافت کنید.

«نمایش ایده» همین مسیر را با یک راهنمای پنج‌مرحله‌ای اجرا می‌کند؛ آغاز راهنما دمو را بازنشانی می‌کند. تغییر سناریو، تنظیمات و تصمیم قبلی را پاک می‌کند. با ویرایش فرم، نتیجهٔ قبلی علامت می‌خورد تا دوباره بررسی شود. با ورود تیکت، آخرین درخواست ثبت‌شده محاسبه می‌شود؛ تنظیمات ارسال‌نشدهٔ فرم حفظ می‌شوند.

## ساخت، آزمون و بستهٔ استقرار

```bash
npm test
npm run build
npm run preview
npm run package
```

- `dist/`: فایل‌های استاتیک؛ محتوای همین پوشه را در ریشهٔ هاست قرار دهید.
- `release/TwinSight-static.zip`: فایل‌های آمادهٔ میزبانی استاتیک؛ `index.html` در ریشهٔ ZIP است.
- `release/TwinSight-runflare.zip`: بستهٔ دارای Dockerfile برای استقرار Docker در رانفلر یا میزبان سازگار.

سایت در زیرمسیر هم کار می‌کند؛ فایل‌ها نسبی و مسیر صفحه‌ها از نوع hash هستند. هیچ API، دیتابیس، secret یا سرویس خارجی برای اجرای دمو لازم نیست. Docker فقط روش بسته‌بندی میزبانی است و به محصول قابلیت تازه‌ای اضافه نمی‌کند.

برای گزینهٔ ایرانی و محدودیت‌های پلن رایگان، [راهنمای استقرار](docs/DEPLOYMENT.md) را بخوانید. GitHub Pages در این پروژه فعال نمی‌شود.

## ساختار

- `public/`: رابط فارسی RTL با فونت محلی Vazirmatn، سناریوها و موتور قواعد ثابت.
- `scripts/`: سرور محلی، build و بسته‌بندی ZIP بدون وابستگی.
- `tests/engine.test.mjs`: محاسبات اقتصادی، حدود ورودی، استقلال نتیجه‌ها و به‌روزرسانی مرتبط.
- `Dockerfile`: میزبانی سبک با Node استاندارد روی پورت ۸۰۸۰.
- `docs/`: معماری، طراحی، استقرار، دمو و وضعیت بررسی.

نتیجه‌ها و تصمیم‌ها فقط در حافظهٔ همان صفحه‌اند؛ با reload یا بازنشانی حذف می‌شوند. هیچ دادهٔ واقعی یا محرمانه وارد نمونه نشده است.
