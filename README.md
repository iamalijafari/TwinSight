# TwinSight — تیم BridgeX

**پیش از انتشار، مسیر اثر تغییر را از سرویس‌ها تا مشتری ببینید.**

نسخهٔ ۲، یک MVP کلیک‌پذیر فارسی برای ارائهٔ داوری است: HTML، CSS و JavaScript ساده با فونت محلی Vazirmatn. بدون .NET، دیتابیس، LLM، کلید API یا وابستگی npm. داده‌های فروشگاه «سپهر تجارت» کاملاً ساختگی‌اند.

## اجرای سریع روی مک

اگر Node.js 22 یا جدیدتر دارید، نصب دیگری لازم نیست:

```bash
cd /Users/alijafari/Desktop/Pol/TwinSight
npm run dev
```

آدرس: http://localhost:8080

بررسی نسخه و نصب Node در صورت نیاز، با Homebrew موجود:

```bash
node --version
brew install node
```

`npm install` و .NET SDK لازم نیستند. اگر مسیر پروژه فرق دارد، `cd` را متناسب با آن تغییر دهید. پورت دیگر:

```bash
npm run dev -- --port 8081
```

اگر Python 3 از قبل دارید، بدون Node هم می‌توانید رابط را اجرا کنید:

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory public
```

فایل `index.html` را مستقیم با `file://` باز نکنید؛ ماژول‌ها و JSON به HTTP نیاز دارند. پس از اجرای سرور، اینترنت لازم نیست.

## مسیر ارائهٔ دو دقیقه‌ای

1. از «تعویض درگاه پرداخت» شروع کنید؛ نمای سازمان از قبل آماده است.
2. «بررسی پیامد تغییر» را بزنید: در روز هفتم شاخص اثر ۵۹٫۹ از ۱۰۰ است.
3. در نقشه روی «گزارش فروش» بزنید: پرداخت → سفارش‌ها → گزارش فروش. شواهد را باز کنید.
4. اثر را روی خریداران موبایل، فروشندگان و مشتریان سازمانی ببینید. روزهای دیگر و وضعیت فعلی نقشه هم قابل انتخاب‌اند.
5. «مقایسه با انتشار تدریجی» را بزنید: با همان ورودی‌ها شاخص اوج به ۳۷٫۱ می‌رسد. کاهش حدود ۳۸٪ حاصل ضریب ثابت دمو است.
6. از «گزارش تصمیم»، JSON را دریافت کنید یا با چاپ مرورگر PDF ذخیره کنید.
7. «بهبود گزارش فروش» را امتحان کنید؛ اثر به همان سرویس محدود می‌ماند. «شروع دوبارهٔ دمو» همهٔ نتایج را پاک می‌کند.

دکمهٔ «راهنمای دمو» همین مسیر را در پنج مرحله نشان می‌دهد و یک سناریوی نمونه اجرا می‌کند.

## چرا Knowledge Base قابل ویرایش نیست؟

در این نسخه «نمای سازمان» آماده و فقط خواندنی است. کاربر برای هر تغییر، منابع را انتخاب یا مدل را بازسازی نمی‌کند. سناریو روی نمای ثابت اجرا می‌شود و آن را تغییر نمی‌دهد.

در محصول واقعی، دانش سازمان شامل سرویس‌ها، روابط، رخدادها و مستندات است؛ با دریافت دادهٔ تازه و کنترل دسترسی به‌روز می‌شود. این کار با تغییر مدل زبانی یا بازآموزی آن یکسان نیست. اصلاح دستی ساختار، در صورت نیاز، کار مدیر با ثبت نسخه و تاریخچه خواهد بود. این قابلیت‌ها در MVP پیاده نشده‌اند.

## ساخت و استقرار

```bash
npm run build
npm run preview
```

`build` بررسی نحوی JS و خواندن JSON را انجام می‌دهد، سپس سایت را در `dist/` کپی می‌کند. سرور محلی فقط ابزار نمایش است؛ روی هاست به Node یا Python نیاز نیست. تمام فایل‌های داخل `dist/` را می‌توان روی یک میزبان استاتیک گذاشت. مسیرهای فایل نسبی‌اند و زیرمسیر `/TwinSight/` هم کار می‌کند.

### GitHub Pages؛ انتخاب پیشنهادی برای این دمو

یک بار در ریپازیتوری، `Settings → Pages → Build and deployment → Source` را روی **GitHub Actions** بگذارید. سپس با پوش روی `main`، workflow فایل‌های استاتیک را می‌سازد و منتشر می‌کند. آدرس مورد انتظار پس از انتشار موفق:

https://iamalijafari.github.io/TwinSight/

این یک زیردامنهٔ رایگان است، نه دامنهٔ اختصاصی. برای ریپازیتوری عمومی GitHub Free قابل استفاده است؛ ریپازیتوری خصوصی به پلن مناسب نیاز دارد. منبع: [مستند GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

روی Pull Request فقط build و artifact قابل دانلود تولید می‌شود؛ استقرار انجام نمی‌شود. در تب Actions، خروجی `twinsight-static` را برای استقرار دستی روی میزبان دیگر دریافت کنید. secrets یا کلید خارجی لازم نیست. workflow تا زمانی که شما فایل‌ها را پوش نکنید اجرا نمی‌شود.

## ساختار کوچک پروژه

- `public/`: کل سایت، موتور ساده، JSON ساختگی و فونت محلی.
- `scripts/serve.mjs`: سرور نمایش محلی با Node استاندارد.
- `scripts/build.mjs`: آماده‌سازی خروجی استاتیک.
- `.github/workflows/pages.yml`: build و انتشار پس از پوش شما.
- `docs/`: توضیح معماری، الگوهای طراحی و وضعیت بررسی تحویل.

پروژهٔ تست، API و موتور C# حذف شده‌اند؛ نگهداری یک موتور JavaScript کافی است.

## حدود واقعی نمونه

نقشه، شواهد، سناریو، مقایسه و گزارش کار می‌کنند. داده‌ها، ضریب اثر، تعداد کاربران، تأخیر و شکل زمان فرضی‌اند. شاخص اثر احتمال خرابی نیست و این نسخه مدل آموزش‌دیده یا پیش‌بینی معتبر ندارد. شرح آزاد تغییر فقط ثبت می‌شود؛ سرویس انتخابی و تنظیمات عددها را می‌سازند.

اتصال واقعی به منابع، به‌روزرسانی زنده، ذخیرهٔ پایدار، حساب کاربری و انتشار روی سیستم واقعی وجود ندارد. بارگذاری دوبارهٔ صفحه، نتایج را پاک می‌کند. تصمیم و مسئولیت انتشار با انسان است. گزارش JSON شامل سناریوی اجراشده است؛ تغییر فرم تا اجرای دوباره گزارش قبلی را عوض نمی‌کند.

راهنمای انتقال از نسخهٔ قبلی در [docs/MIGRATION.md](docs/MIGRATION.md) و مبنای طراحی در [docs/DESIGN.md](docs/DESIGN.md) آمده است.
