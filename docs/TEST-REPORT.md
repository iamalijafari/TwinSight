# گزارش واقعی بررسی — ۲۰۲۶-۱۰-۰۱

این گزارش نتیجهٔ بررسی‌های همین محیط است؛ برنامهٔ محلی .NET، مرورگر یا سرویس AI واقعی به‌جای تست‌های زیر فرض نشده‌اند.

## موفق در محیط ساخت

| بررسی | نتیجه | حد شواهد |
|---|---|---|
| `node --check` برای `app.js`, `engine.js` و دو ابزار بررسی | موفق | صحت نحوی JavaScript؛ نه اجرای مرورگر |
| `node --test tests/engine.test.mjs tests/ui.test.mjs` | **۱۱ تست موفق، ۰ شکست** | ۸ گروه آزمون موتور و ۳ آزمون جریان UI با test double |
| ترکیب‌های کنترل موتور | **۶۴۰ ترکیب موفق** | ۸ target × ۴ نوع × ۵ دامنهٔ انتشار × ۲ حالت canary × ۲ پوشش تست؛ محدودبودن عددها و جمعیت‌ها بررسی شد |
| داده و فایل‌ها | موفق | JSON معتبر، سازگاری IDهای گراف/شواهد/گروه‌ها، XML معتبر پروژه و لوگو، IDهای یکتای HTML، وجود assetها، انطباق refهای JavaScript و labelها |
| سرویس استاتیک واقعی Python روی loopback | موفق | پاسخ HTTP ۲۰۰ و محتوای غیرخالی برای HTML، CSS، دو JS، fixture و SVG؛ JavaScript در مرورگر اجرا نشده |

## موارد پوشش‌داده‌شده در تست‌ها

- ساخت مدل نیازمند GitHub و منبع دوم؛ منبع ناشناخته و تکراری رد می‌شوند.
- سناریوی پایه Payment به شاخص ۵۹٫۹ می‌رسد؛ مسیر Analytics از Payment و Orders عبور می‌کند؛ Identity/Gateway اثر upstream نمی‌گیرند.
- canary، پوشش تست بیشتر و انتشار محدود در قواعد این دمو شاخص را کاهش می‌دهند.
- حذف منبع باعث حذف شواهد و کاهش پوشش می‌شود و ریسک را کاذب پایین نمی‌آورد.
- targetهای متعدد، ورودی‌های نامعتبر، twin قدیمی و محدودبودن شاخص‌ها بررسی شدند.
- متن آزاد، کد یا دستور درج‌شده در آن به‌تنهایی عدد را تغییر نمی‌دهد.
- خط زمانی در نقاط ثابت و بین آن‌ها بررسی شد.
- جریان رابط در حالت آفلاین: ساخت، شبیه‌سازی، انتخاب سرویس با رویداد صفحه‌کلید، تغییر زمان، امروز/آینده، پین، مقایسه، توضیح قواعد، رویداد دانلود و ابطال مدل.
- رابط با API ساختگی: ساخت/محاسبهٔ دیررس پس از تغییر ورودی کنار گذاشته می‌شود؛ خطای سرور نتیجهٔ قبلی را حفظ می‌کند و بی‌خبر به حالت آفلاین نمی‌رود.
- پیشنهاد AI ساختگی: سرویس‌ها و نوع تغییر تا کلیک صریح پذیرش تغییر نمی‌کنند؛ متن شامل markup به‌صورت text باقی می‌ماند.

**DOM آزمایشی مرورگر نیست.** تست رویداد، وضعیت و خروجی متنی را بررسی می‌کند؛ تفسیر CSS، layout، bubbling طبیعی کامل، اعتبارسنجی native فرم، focus واقعی، دانلود واقعی و رندر SVG را ثابت نمی‌کند. تست XSS در این سطح صرفاً استفاده از text node را نشان می‌دهد، نه تضمین جامع امنیت.

## کنترل پیش از ارائه

1. روی دستگاه خود `dotnet build` و آزمون C# را اجرا کنید؛ خطای build را پیش از معرفی دمو رفع کنید.
2. سرور محلی را اجرا و آزمون API/مرورگر را انجام دهید؛ تصویر desktop و mobile را ببینید.
3. حداقل یک بار مسیر payment، canary و مقایسه را کامل تمرین کنید؛ سوییچ حالت اجرا را در سربرگ بررسی کنید.
4. fixture و کلیدها را با اطلاعات واقعی مشتری جایگزین نکنید؛ اتصال سازمانی به دامنهٔ کار دیگری نیاز دارد.
5. در ارائه صریح بگویید این اعداد شبیه‌سازی قواعد دمو هستند؛ ادعای پیش‌بینی معتبر یا محصول آمادهٔ بهره‌برداری نکنید.
